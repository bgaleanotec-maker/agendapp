El proyecto: AgendApp

Plataforma web para que consultorios y médicos independientes gestionen sus citas.

  • El paciente agenda, cancela y recibe recordatorios.
  • Pre-triaje de síntomas asistido por un motor de reglas.
  • El médico administra su agenda; el administrador supervisa.
Flask · SQLAlchemy · PostgreSQL · desplegado en Render

Tipos de prueba y criterios de aceptación

Niveles aplicados

  • Unitarias — motor de pre-triaje aislado
  • Integración — rutas + ORM + base de datos
  • Sistema — suite completa y rendimiento
  • Aceptación — escenarios de usuario en producción
  • Regresión — toda la suite tras cada cambio

Criterio global

100% de los casos críticos y altos en verde
0 defectos críticos abiertos
Meta de cobertura 80% en funciones críticas

El objetivo (confianza) no es la métrica (% de cobertura).

pytest: alcance y conexión con la clase

¿Qué es y hasta dónde llega?

  • Framework de pruebas de Python: ejecuta y reporta solo.
  • Alcance: una misma suite cubre los niveles unitario, de integración y de sistema.
  • Fixtures (conftest.py): entorno aislado y reproducible con BD en memoria.
  • Cobertura con pytest-cov; se corre en cada cambio.
class TestMotorIA:
  def test_prescreen_urgente(self, client):
    r = client.post("/api/ai/prescreen",
        json={"text": "dolor pecho ..."})
    assert r.get_json()["level"] == "urgente"

Cómo conecta con lo visto en clase

  • Modelo V: un comando ejercita unitario → integración → sistema.
  • Automatización → regresión: red de seguridad ante cada cambio.
  • Entorno controlado y reproducible, condición de una prueba confiable (Singh, 2011).
  • Técnicas de diseño (partición, valores límite, decisión) materializadas en cada caso.
  • Verificación y validación llevadas a la práctica (SWEBOK).
